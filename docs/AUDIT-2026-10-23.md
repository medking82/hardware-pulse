The former `SEC-01` investigation is implemented in this iteration. Unsafe or busy paths fail closed rather than falling back to direct writes. Legitimate junction-based redirection is also refused by these write paths. Existing unrelated runtime children are preserved, and the application never consumes them as its own outputs.

Directory pins request `LIST_DIRECTORY | READ_ATTRIBUTES`; an attributes-only handle did not prevent rename in the first acceptance test. Publication uses the native same-directory rename form because the Win32 path-based wrapper reopened the pinned directory. ACL changes use `MAXIMUM_ALLOWED` handles to suppress automatic propagation into existing children. These choices follow the [CreateFile sharing contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), [same-directory rename contract](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information) and [SetSecurityInfo propagation rules](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setsecurityinfo).

Modern Windows uses extended rename semantics so an existing reader keeps the complete old snapshot while new readers see the new file. A reader denying delete sharing still blocks replacement, preserving the old document. Unsupported information classes/filesystems fall back to classic same-directory rename; a busy target can then fail safely. Neither path drops the source handle or directory pins to retry a path-based write. State-directory initialization and the Claude snapshot read/compare/reset gate use the same pinning boundary.

## Maintainability

- Three independent temporary-file implementations now use `AtomicFile`, with the Windows handle operations in one place. `RuntimeDirectory` owns only the installed runtime ACL policy. Size limits, encryption and provider/session policy remain with their existing owners.
- Installer recovery no longer stores and rewrites previous STOP bytes. Existing signals are preserved; setup only owns its own new file. This removes the two overwrite operations instead of adding checks around them.
- No package, framework, background service, repository-wide formatting pass or new configuration layer was added. Existing .NET Framework build paths remain supported; the modern adapter includes the same helper to preserve source compatibility.
- Existing durable flushes remain on credentials and Claude snapshots. Two-second telemetry publication does not gain a forced disk flush. No CPU, memory or latency improvement is claimed without a comparable benchmark.
- Corrected the obsolete UI specification that contradicted the explicit forced Manual Refresh behavior already shipped in 0.6.65. Quota request behavior was not changed by this iteration.
