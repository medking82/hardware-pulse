# Claude 额度刷新恢复（Windows 0.6.46）

[English](CLAUDE-QUOTA-REFRESH.md)

## 实际观察到的问题

已安装的 0.6.45 在收到 HTTP 401 后保留了三十分钟的本地认证冷却。即使 Claude Code 随后更新凭据，手动刷新仍会跳过 Claude，仅刷新其他来源，界面没有解释原因。使用当前凭据进行的一次独立查询成功，证明当时的登录有效，但不能确定此前认证被拒绝的原因，也不能证明登录能一直自动续期。

## 修复范围

- 设置 → AI Quota → 刷新额度会分别显示各个已启用来源的进度、完成结果或下一次允许请求的时间。卡片上的 ↻ 按钮只刷新该来源；卡片状态也显示刷新中或请求暂缓。
- 只有已启用、非本地快照、上次远程结果为 Login required 的 Claude 来源，才能缩短认证退避。下次请求至少距离失败观察五分钟。手动刷新与已知来源的修改信息变化遵守相同下限；进行中的请求不会因再次点击而额外排队。
- 使用现有只读检查，最多每三十秒检查一次已知被拒绝来源的修改信息。不增加凭据来源、token 内容读取、文件监听器、进程启动或凭据写入。没有已知的失败来源版本时（包括重启后），自动恢复继续遵守已保存的重试时间；用户仍可手动刷新。
- 当前 HTTP 429、Retry-After、权限及网络错误的等待时间不能通过此路径缩短。认证重试不会清除限流计数，只有查询成功才会重置。持久化调度仍保护来源开关、来源切换及重启。
- 请求开始前，将保存的预约明确标为 Refresh pending，并记录预约时间，防止重启后将尚未完成的请求误认为已完成的认证失败。调度文件格式不变，仍只保存允许的调度信息。
- 登录仍由 Claude Code 管理。来源信息变化不代表登录一定有效，重新检查仍可能失败，且必须限制请求频率。本次不提供无人值守 token 续期，也不将仅支持模型请求的 setup token 当作额度凭据。

## 验证与回退

Core 模拟测试覆盖恢复的 401 状态、五分钟下限、连续点击、崩溃后的请求预约、限流历史、其他错误的等待规则以及成功后的正常周期。隔离 WPF 测试覆盖真实卡片与按钮事件、设置页反馈、刷新进度、成功、暂缓请求，以及注入的模拟来源检查；不访问真实凭据，也不请求服务商接口。

发布前运行 scripts/Validate.ps1 -ModernCore，并构建、签名对应版本的 Windows 安装包。真实凭据跨过期时间后的续期、长时间服务可用性及全新机器安装仍需单独验证。

回退时安装上一稳定版。现有设置与 schema-1 调度信息保持兼容，不涉及凭据迁移或撤销。
